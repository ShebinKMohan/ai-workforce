# AI Workforce: installed-runtime harness research

Research date: 13 September 2026. Source audit base: `cabb838`, with the runtime/model/effort and AI intake refinement in progress in the shared checkout. This document compares documented mechanisms and source-visible gaps; it is not an implementation or acceptance receipt.

## Product direction

Use **AI Workforce** as the public name, with **“A local harness for your coding agents”** as the descriptor. The shorter name explains the product to developers and other users; “agentic” can describe its orchestration in technical material. This is an editorial recommendation, not a measured claim that one name is more popular in September 2026. Preserve the `workforce` CLI, state directories and record identifiers for compatibility unless a separate migration changes them.

The useful pattern is to let each installed runtime keep its model/tool loop while AI Workforce owns project context, task contracts, routing, capacity, file delivery, evidence and the user experience. A second framework does not inherently make routing faster. OpenAI's App Server exposes conversation, turn and item events; GitHub's SDK similarly communicates with a CLI server through JSON-RPC and manages its process lifecycle. Both are concrete examples of building an application around an existing agent runtime. [Codex App Server](https://learn.chatgpt.com/docs/app-server), [GitHub Copilot SDK](https://github.com/github/copilot-sdk).

## Recommended implementation order

1. **Complete the requested input and visibility work.** Add multiple-file selection, drag/drop and removable attachment chips; expose supported formats and actionable failures. Bind attachment identities to the durable request and carry them into the selected runtime and delegated work. Use native image input for a supported image rather than asking a tool-free intake to read a path. The selected model's capabilities and the installed protocol determine what is available. Codex currently documents text, remote image and local-image turn items; that does not establish arbitrary audio/video/PDF support. [Codex typed turn inputs](https://learn.chatgpt.com/docs/app-server).

2. **Add completion and attention notifications (FR075).** Default to a quiet interface, offer an explicit “Notify when work needs attention” control, and request browser permission only from that action. Notify once for a new terminal or blocked transition, with a link to its exact task. Seed the first loaded history without alerts; persist deduplication so reconnects do not replay old notifications. Keep browser-denied and unsupported states usable. This is a bounded browser feature, not a claim of background delivery after the browser/server closes. Codex separates completion notifications from permission/question notifications and allows background-only delivery. [Notifications](https://learn.chatgpt.com/docs/notifications).

3. **Add explicit “Follow up on this task” (FR025/FR037).** Start with a new request referencing the original request, exact prior final response, candidate identity and relevant accepted decisions. Show the context source near the composer. Keep current independent-send semantics unless the user selects follow-up. Later, native session resume can reduce repeated context work, but must preserve project/runtime identity and process ownership. Claude's session documentation explicitly separates conversation persistence from filesystem persistence. [Claude sessions](https://code.claude.com/docs/en/agent-sdk/sessions).

4. **Expose reusable project instructions and skills (FR013/FR017/FR024).** First show which local instruction/skill sources the runtime actually loads and where they came from; then allow deliberate assignment of supported resources to an agent. Use names/descriptions for selection and load full instructions only when relevant. Do not automatically enable every discovered hook or external MCP server. OpenAI's skills use this progressive disclosure pattern. [Build skills](https://learn.chatgpt.com/docs/build-skills).

5. **Improve candidate delivery and controlled recovery (FR046/FR059).** Offer the recorded patch, report and check receipts directly from task evidence. A later restore/apply action must identify its target and detect changed or dirty source. Claude checkpoints illustrate why “undo everything” is an incorrect promise: shell-command edits and many subagent changes are not restored by its session rewind. [Claude checkpoint limits](https://code.claude.com/docs/en/checkpointing).

The first two items are the best fit for the current UI and attachment implementation pass. Follow-up semantics and skills management deserve bounded subsequent changes with persistence and adapter tests; adding a disconnected settings screen would not complete them.

## Architecture and measurement implications

Keep Control Center as the AI decision maker for reply, clarification and department routing, and keep the scheduler in deterministic code. Department heads propose assignments; code reserves capacity and enforces the roster. Animate actual persisted transitions and message receipts. A brief “sending” animation may show local submission, but should switch to “received” only after the server acknowledges it. Replay visual communication only as explicitly labeled replay, and stop live pulses when ownership settles. Display the actual phase and actor alongside motion so animation is never the only evidence.

Measure receipt latency, routing time, worker start time and verified-result time separately. Prefer compact handoffs and on-demand detail; retain the collapsed chat traces. The strongest lesson from OpenAI's February harness article is to make repository knowledge, observable application behavior and architectural constraints available to agents, then enforce essential invariants mechanically. Its internal workflow is not evidence that extra orchestration layers improve every task. [Harness engineering, 11 February 2026](https://openai.com/index/harness-engineering/).

Do not silently replace the installed Claude CLI with the Agent SDK as an authentication shortcut. The SDK documentation states that offering third-party claude.ai login or rate limits requires prior approval and directs SDK builders to its API-key methods. This constraint is already acknowledged in our plan and matters for any public SDK migration. It does not change the user's requested local-runtime architecture. [Agent SDK integration guidance](https://code.claude.com/docs/en/agent-sdk/overview).

No code, assets or prompts from the researched harnesses were copied into implementation by this research task. No paid runtime turn or comparative performance benchmark was run for this document. Completed integrations, supported file types and live proof belong in the corresponding implementation evidence record.

## Implementation outcome from this pass

The implementation completed the first two priorities: runtime-backed multimodal uploads, exact local project selection, recorded communication animation and opt-in task notifications, alongside the AI Workforce name and installed model/effort controls. A live Codex GPT-5.5 intake correctly read a text brief and the user's annotated PNG in the same request. The final build and type check passed, with 1,626 tests passing and 32 skipped. The notification control reported the browser's denied permission honestly; native Claude input and downstream attachment delivery have automated coverage, without a new live Claude run in this pass.
