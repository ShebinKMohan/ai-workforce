## What the adversarial pass caught

Three independent verifiers converged on one blocking defect: acceptance pinned the check *command*
to the base revision but ran test *code* from the worker-writable candidate. A worker that deleted the
suite and fixed nothing was reported `accepted` with `verifier_executed` evidence. The initial evidence
file claimed the opposite; that claim was false and is preserved in the superseded record.

Reproduced by hand before and after:

| Scenario | at bbc5baa | at 64e1a51 |
| --- | --- | --- |
| Worker rewrites the test suite, fixes nothing | accepted, exit 0 | not accepted, exit 4, criterion `compromised` |
| Worker applies a genuine fix to src/ only | accepted, exit 0 | accepted, exit 0 |

Nine further defects were fixed in the same commit: escaped writes and mid-turn runtime death now block
acceptance; Ctrl+C exits 130 in ~1s with no surviving process group; runTimeoutMinutes is enforced; the
lock resists arbiter replacement; `doctor --agents` probes the executable the config names; a flaky
replay-fixture race was removed; a runner executing zero tests yields `no_tests_executed`.
